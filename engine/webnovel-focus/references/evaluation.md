# 评估方法

判定质量靠"抽查 + 标注 + 盲测"三件事，不要靠感觉说"应该判得挺准"。

## 一、新书抽查（每次都要做）

`run.py doctor` 生成的前几章抽查页（`<输出目录>/confirm/book.html`）就是第一道评估：
判定标记默认打开，每段带分层标签，悬停看判定证据，点一下可永久保留原文。

交给用户时问三件事：判定是否合理（哪一类判错）、口味档位、源文件问题怎么处理。
用户给出的错判要落到**类别**上（写景 / 面板 / 对话 / 短句 / 解说腔 / 复述），
因为每一类对应 `detect_rules.py` 里一条具体判据，落到类别才能改对地方。

## 二、标注集与指标

- **标注集**：请读者标 2~3 章，段落级 `{关键 / 普通 / 零信息}`。几百段就够看出问题。
- **主指标**
  - 关键情节误淡化率（目标 0~1%）——把 `关键` 判成了 `fade`/`zero`
  - 淡化字数占比——读者的体感，太低等于没干活，太高说明在乱判
- **次指标**
  - 零信息类判死的准确率与召回率（求票、水印、复述）
  - 人名候选里有几个是假名（假名会污染"人名首次出现"这个关键锚点）
- **人工盲测**：原版与淡化版并排读，问"有没有漏掉重要内容"。这是唯一能发现
  "整体读起来变味了"的方法，指标看不出来。

## 三、用抽样审查代替逐段读

```
python scripts/run.py sample <analyzed.json> --tier fade --n 25 --context 1
```

- `--tier` 选要看哪一层：判得最该怀疑的是 `fade`/`zero`（漏判关键情节代价最大），
  其次是 `plot`（有没有把注水判成情节）。
- `--context 1` 带上文，判断这段是不是真的没信息。
- 种子固定 → 同一份 `analyzed.json` 每次抽到同一批；改规则前后（`--seed` 不变）
  可以直接对比命中情况。
- 要逐段看就用 `report.txt`：每段都写了 `kind`、`score`、命中的 `flags`/`anchors`
  和 `evidence`（哪条规则命中的）。定位误判时先看 evidence，再决定改哪条判据。

## 四、判读标准

| 抽样层 | 看到什么算问题 | 对应改哪里 |
|---|---|---|
| `fade` / `zero` | 出现转折、伏笔、关系变化、事件结果 | 锚点权重或该类的判据太激进（先看 evidence） |
| `plot` | 整段写景、复述、求票、纯解说 | 锚点词误命中（`EXPOSITION_MARKERS` 覆盖不足） |
| `mid` | 大量同质段落挤在这一层 | 分数分布太平，检查 `tier_of` 的阈值 |

## 五、改规则后的回归

1. 至少**两本风格不同的书**（一本短段多、一本长段多；一本有面板、一本没有）。
   只在一本书上调参，下一本必翻车——第四节到第六节的每一条约束都是这么发现的。
2. 同 `--seed` 重跑相同层的抽样，比较改动前后：误报有没有变成漏报（漏报更严重）。
3. 长度类改动先看 `doctor` 的基线报告：新阈值会命中多少比例的段落，超过 10% 就说明
   它在描述作者风格，不是注水。
4. 记录改动前后的分层占比（`build` 的最后一行就是）。占比突变通常意味着判据写错了，
   而不是"判得更准了"。

## 六、当前没有的东西

- 没有自动化标注集和回归脚本，指标靠人工抽样近似。
- 没有 LLM 语义打分层，所以"模糊区"的准确率上限就是规则层的上限；
  代价是零成本、可复现、离线可跑，这个取舍是刻意的。
- 没有跨更多章的复述检测，远距离复述当前检不出来。
