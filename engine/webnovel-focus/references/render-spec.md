# 载体与处置规格

判定层输出的是中立结果，这份文件规定它怎么变成阅读体验：分层怎么映射到处置、
偏好怎么配置、什么规模用什么载体、模板层有哪些非显然的坑。

## 一、分层 → 处置映射

判定给每段一个 `kind`（结构类型）和一个 `score`（推进度 0~1），
`tiers.py` 把它们映射成五个默认分层，`render.py` 再给每个分层一个淡化系数：

| 分层 | 判据 | 行为 | `dim`（0 = 不动） |
|---|---|---|---|
| `plot` | score ≥ 0.68 | 加深（加重字重、颜色压深） | 0.00 |
| `mid` | 0.52 ~ 0.68 | 原文 | 0.10 |
| `weak` | 0.38 ~ 0.52 | 轻微淡化 | 0.28 |
| `fade` | 0.12 ~ 0.38 | 明显淡化 | 0.58 |
| `zero` | < 0.12 或零信息类 kind | 重度淡化 | 0.82 |
| `sep` | 纯装饰行 | 渲染成分隔线，不显示文字 | — |

实际不透明度 = `1 - 强度 × dim`，强度由读者在页面顶栏控制（默认 0.55）。所以
「原汁原味」档下所有分层都是原文，「只看剧情」档下注水类几乎不可见。

零信息类（`author_note` / `watermark` / `punctuation`）无论偏好如何都进 `zero` 层：
它们不是口味问题。读者手动点过的段落永久保留原文（`.keep`，优先级最高）。

## 二、读者偏好配置

三层渐进，别把难题甩给读者：

1. **预设档**：原汁原味（强度 0）/ 平衡（0.55，默认）/ 只看剧情（1.0）
2. **分组开关**（各自 保留 / 淡化）：系统面板、写景、短句连发、复述、日常对话、作者话+水印
   —— 对应 `body.keep-<flag>`，作用在 `data-flags` / `data-kind` 上
3. **滑杆微调** + 即时预览；**手动纠错**：点段落永久保留，点面板块折叠/展开
4. **偏好沉淀**：按书保存一档；同书不同卷口味不同时另存一档

面板的四种处置要在实现里都可选，默认**折叠成一行摘要**：读者不需要读数值，但需要知道
"解锁了技能"：保留原文 / 淡化 / 折叠成一行摘要 / 抽到章末附录。当前模板实现了前三种
（顶栏「系统面板」下拉框）。

**面板里的异常字段（新技能、称号变化、倒计时、未知字段）永远保护**：读者关掉面板的本意是
"不想看数字"，不是"想错过伏笔"。

## 三、载体规格

微信读书、起点 App 这类阅读器不允许自定义 CSS，字体淡化在里面做不了。可落地载体是
自带阅读器的 HTML（可交互、能即时预览）、EPUB（可导入、有样式，整本书的正路）、
PDF（只读、不分页交互）。三者的生成方式见第四节。

### 单文件还是分章

实测 369 万字的《序列玩家》：

| 形态 | 大小 | Chrome 加载 |
|---|---|---|
| 全书单文件 | 27.7 MB / 11 万 DOM 节点 | 11.18s |
| 目录页 | 252 KB | 0.73s |
| 单章 | 中位 30 KB | 0.55s |

**结论：超过约 40 万字必须分章。** `render.py` 的 `SPLIT_AT_CHARS = 400_000` 是这条线，
`--mode auto` 按字数自动选；分章输出 `index.html`（目录页，带每章的情节/淡化段数）+
`ch####.html`。

### 偏好怎么跨页传递

用 **URL 查询串**（`s` 强度 / `p` 面板模式 / `k` 保留分组 / `e` 加深 / `m` 判定标记），
翻页时由模板里的 `syncLinks()` 带到下一页。**不要用 localStorage**：`file://` 下各浏览器
的同源策略不一致，查询串是唯一可靠的跨文件传递方式。

`--marks` 会把"显示判定"烤成页面默认值；查询串里显式写了 `m=` 时以查询串为准。

## 四、EPUB / PDF 交付规格

读者调完偏好后要能把"这版书"带走。**不要用 txt**：txt 没有样式，"淡化"只能靠删段或
加文字标记，等于把视觉分级降级成内容删减。EPUB 和 PDF 都能真淡化，
`run.py export --format epub|pdf` 就是这两个出口。

### 分层 → 视觉

和阅读页同一套系数（`render.py` 的 `DIM`）：不透明度 = `1 - 强度 × 系数`。
EPUB 另有一层换算，因为不是所有阅读器都认 `opacity`：

| 杠杆 | 怎么写 | 适用 |
|---|---|---|
| `--lever color`（默认） | 把不透明度按 alpha 混合到纸张白，算出等价灰色写进 `color` | 兼容性最好；深色主题下仍读得出来。DESIGN 里"Kindle 对 opacity 支持不完整，需用灰色替代"就是这个 |
| `--lever opacity` | 直接写 `opacity` | 视觉最接近阅读页；被忽略时退回原文，不会出错 |

拿不准先跑 `scripts/make_css_probe.py` 生成样式探针 EPUB，导进目标阅读器看哪些手段活着，
再定 `--lever`。分层的深浅必须单调（`tests/check_pack.py` 会断言）：
强度 0.55 下 情节 `#111111` → 普通 `#333333` → 偏水 `≈#525252` → 注水 `≈#747474` → 零信息 `≈#8f8f8f`。
强度 0 时淡化类不再写任何样式（只有"重点加粗"还在，跟阅读页拉到底一样）。

### EPUB（推荐用于整本）

- 结构：`mimetype`（第一个条目且不压缩）→ `META-INF/container.xml` → `OEBPS/content.opf`
  （EPUB3，带 `dcterms:modified`）→ `nav.xhtml` + `toc.ncx`（给只认 EPUB2 的老阅读器）
  → 每章一个 `ch####.xhtml` + 一份 `style.css` + 文本封面页。
- 样式写两遍：`p.t-<层>` 写在样式表里，**同时**在段落上写行内 `style`。
  阅读器若清洗掉 `<style>` 块，行内还能兜底；两处声明必须一致，
  `tests/check_pack.py` 会比对，防止两套机制漂移。
- 字体不内嵌，交给阅读器（内嵌 CJK 字体会把包撑到几十 MB，得不偿失）。
- 段落上只给非普通层写样式：普通层是绝大多数，写上去等于白增体积。
- 面板默认**全部保留**（`--panel full`）：EPUB 里读者没法展开折叠块，
  折叠等于丢内容。要折叠用 `--panel collapse`，会写成首行 + `〔面板：略去 N 行〕`。
- 零依赖，纯 `zipfile` + 手写 XHTML。

### PDF（只读、不交互）

- 路线：`render.render_print_html()` 渲一份静态打印页（去掉控制栏与脚本、面板强制展开、
  强度烤进 `:root`），再用本机 Edge/Chrome 无头打印（`--print-to-pdf`，`--user-data-dir`
  指向临时目录，不碰用户配置）。**不依赖 WeasyPrint / wkhtmltopdf**。
- 打印引擎如实渲染 `opacity`，所以 PDF 和阅读页所见一致。实测最黑灰度：
  情节 18 / 普通 47 / 注水面板 100（`tests/check_pack.py` 用 poppler+Pillow 量的）。
- 页面尺寸用 `@page { size: A5 }`（可选 A4 / B5 / letter），`break-inside: avoid` +
  章首 `break-before: page`。
- 实测：30 章 / 6.9 万字 → 248 页 / 3.6 MB / 5.3 s；60 章 / 27 万字 → 1,062 页 / 11 MB / 12.9 s。
  **所以整本书不要打成一个 PDF**（369 万字会是上万页、上百 MB，浏览器也可能卡死）：
  大书用 EPUB，或用 `--chapters-per-file N` 拆卷，或用 `--from/--to` 只打一段。
- 打印用的 HTML 会留在 PDF 旁边（`*.print.html`）：想调页边距，用浏览器打开它
  "打印 → 另存为 PDF"即可，不必重跑。

### 已知边界

- PDF 里面板无法折叠（打印是静态的），一律展开显示，靠淡化表达"这类内容可以跳"。
- EPUB 的样式能不能活，取决于阅读器；因此才有 `--lever` 两个选择与那个样式探针。
- 微信读书、起点 App 不允许自定义样式，也不吃本地 EPUB；EPUB 的目标是
  Apple Books、静读天下、多看、Calibre 这类能导入文件的阅读器。

### 命名与留痕

- EPUB 默认 `<书名>.epub`，PDF 默认 `<书名>.pdf`（拆卷时 `<书名>-001.pdf`…），都可用 `-o` 指定。
- PDF 旁边的 `*.print.html` 是打印源，故意留着：想改页边距不用重跑引擎。
- 包里的书名、章名、生成参数（强度、杠杆、面板处置、保留分组）写进 OPF 的
  `dc:description`，读者日后翻出来还知道这份是怎么生成的。

## 五、产物布局与命名

```
build/<书名>/
├── prescan.json / prescan.txt   源文件体检（build 时会刷新）
├── parsed.json                  解析结果
├── analyzed.json                判定结果
├── report.txt                   逐段对照表
├── book.html                    单文件阅读版
├── index.html + ch####.html     分章阅读版
├── <书名>.epub                  EPUB 交付版
├── <书名>.pdf / <书名>-001.pdf  PDF 交付版 + 旁边的 *.print.html
└── confirm/                     doctor 的前几章抽查页（判定标记默认打开）
```

抽查页固定渲染成单文件 `confirm/book.html`；正式版按 `--mode auto` 决定形态。

## 六、模板层的坑（踩过）

- **CSS 特异度相同时靠顺序取胜**：`body.keep-x .p[a~="y"]` 和
  `body[data-preset="z"] .p[a~="y"]` 同分，谁写在后谁生效。所以 `body.keep-dialogue`
  这条"保留"规则必须排在 `body[data-preset="plotonly"]` 压暗规则**之后**，否则
  读者勾了"保留日常对话"却不生效。
- **Jinja 里 `obj.items` 会被解析成字典的 `.items` 方法**，报
  `'builtin_function_or_method' object is not iterable`。模板里传数据别用 `items` 当键名。
- **弯引号会被吞**：正则里直接写 `“”` 在编辑/传输过程中可能丢失，导致对话识别彻底失灵
  （书里用了 3,263 个 `“`）。一律用显式码点 `\u201c \u201d \u300c \u300e`。
- 模板里 `data-marks` 这类"烤进页面的默认值"要和脚本的初始状态对齐：脚本在无查询串时
  读页面上的值，有查询串时以查询串为准。改默认值时要同时看模板和脚本。
- **Jinja 必须开 autoescape**（`Template(..., autoescape=True)`）。正文里偶尔出现 `<` `&`
  （招式名、系统面板、公式），不转义会被浏览器当标签吃掉后半段，页面缺字、导出也跟着缺。
  `tests/check_pack.py` 会抽几段逐字比对，能兜住这类回归。

## 七、依赖与降级

核心链路零新增依赖：Python 3 + Jinja2 必装；scikit-learn 只在重复检测里用到，属于可选。
开发环境（Python 3.14）里 numpy / scikit-learn / scipy / pandas / lxml / Jinja2 都在，
但没有它们也能跑，降级路径见下。

**不需要 jieba**：中文查重和段落相似度用 sklearn 的字符级 n-gram
（`TfidfVectorizer(analyzer="char", ngram_range=(2,4))` + 余弦）就够，这是中文查重不依赖分词
的标准做法，可移植性因此拉满。

sklearn 缺失时 `detect_rules.analyze()` 打印 `[warn] 重复检测跳过` 并继续，其余判定不受影响。
这条降级路径要保留：它让 skill 在没装科学计算栈的机器上仍可用。

## 八、当前实现的边界（别对用户承诺超出范围的能力）

- 只解析 TXT。EPUB / HTML 要先抽成文本。
- 判定是**纯本地规则层**，没有接入 LLM 语义打分。模糊区靠"只打标签 + 读者手动纠错"兜住，
  不存在"语义理解每一段"的能力。
- 没有 DP 区间平滑（设计里的最小淡化长度、最小保留长度、开头若干段不淡化均未接入），
  当前逐段独立判定。
- 面板只到"聚块 + 字段签名"，跨章 diff 与异常字段识别未接入。
- 重复检测只在"前 5 章 + 本章内"比较，跨更远的复述不会被发现。
- 交付载体是 HTML / EPUB / PDF，没有 txt：txt 表达不了淡化，只能靠删段或加标记，
  这条路已经明确放弃。
- EPUB / PDF 都由 `analyzed.json` 离线打包，拿不到"页面里手动点过的段落"——
  那是浏览器里的临时状态。要固化某个选择，就用 `--keep` / `--strength` 明确指定。

要对用户讲清这几条，尤其是"面板数值默认折叠但原文不丢"和"关键情节可能漏判，遇到漏判点
一下就能保留原文"。
