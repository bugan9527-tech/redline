# 网文分级渲染

把网文正文变成分级阅读器：关键情节加深、注水淡化、求票/作者话/水印这类噪音判死，
读者在页面顶栏实时调强度和分组，偏好跟着翻页走。

引擎只做识别，不做审美判断。它输出 `{区间, 类型, 证据, 置信度}`，"水不水"由读者偏好层决定。
所以识别一次、渲染无数次：调偏好不重跑判定。

## 什么时候用

- "这书太水了，想只看剧情""把重要情节标出来""帮我挑重点""几百万字读不动"
- 把已读完或正在读的一本书做成精简阅读版（节选或全书皆可）
- 用户说判定不准，要改判定规则并用抽样回归验证

不适用：文学评论、情节摘要、翻译、单纯排版美化。输入是中文长篇叙事文本。

## 输入与依赖

- 输入是纯文本 TXT（UTF-8 优先，GBK 也能救）。EPUB / HTML 先抽成文本再进来。
  源本身是 HTML 时，尽量保留段落边界：作者话、水印、盗版广告在 HTML 里常是独立节点，
  边界比纯文本好认。
- 依赖 Python 3 + Jinja2；重复检测用 scikit-learn（缺了自动跳过，其余照常）。不需要 jieba。
  EPUB 打包零依赖；PDF 需要本机有 Edge 或 Chrome（无头打印），没有就退回 EPUB。
- 环境由助手自备，不要让用户手动装：缺 Python 3 就自动安装（Windows 用
  `winget install Python.Python.3.12`，macOS 用 `brew install python3`，Linux 用系统包管理器），
  再 `python -m pip install jinja2`（scikit-learn 可选）。装完先验证
  `python scripts/run.py --help` 能跑，再进流程一。
- 脚本用相对 `__file__` 的路径找 `assets/`，整个 skill 目录可以整体搬走。

## 流程一：新书第一次用（必做，别跳）

```
python scripts/run.py doctor <书.txt> [--chapters 3] [--from 1] [-o build/<书名>]
```

doctor 依次做三件事，然后把结果交给用户：

1. **源文件体检**——防盗版反义词替换（`好→坏`、`不→是`、`你→他`…）、`??` 替换、
   编码/换行、章号回退、正文行被误判成章节标题。判据与实测数值见
   [references/judgment-rules.md](references/judgment-rules.md) 的「源文件陷阱」。
2. **风格基线**——段落长度分布、对话密度、标点习惯、章字数。引擎里所有长度类阈值
   都相对这本书的基线算（`detect_rules.py` 的 `book_profile`），这份报告是它们的出处，
   也是"这本书判得准不准"的对照尺。
3. **前几章抽查页**——`<输出目录>/confirm/book.html`，"显示判定"默认打开，
   每段带分层标签，鼠标悬停能看判定证据，点一下可永久保留原文。

**把抽查页给用户，问三件事**（用户没回话之前，不要宣称判定没问题，也不要急着出整本）：

| 问什么 | 怎么问 |
|---|---|
| 判定是否合理 | 让他翻抽查页；错判要说清是哪一类（写景 / 面板 / 对话 / 短句 / 解说腔），别只说"不准" |
| 口味 | 默认「平衡」。只想推主线调「只看剧情」；题材本身就吃日常/数值的人保持默认 |
| 源文件问题 | 体检单里有污染或章号异常时，先问清：读干净区间、照读残文、还是等换源 |

用户说"可以"之后再进流程二。判定有异议时走流程三，别靠猜。

## 流程二：出阅读版

```
python scripts/run.py build <书.txt> [--limit N] [--from N] [--mode auto|single|split] [-o build/<书名>]
```

一条命令串起 parse → detect → report → render，产物都在 `-o` 目录（默认 `build/<文件名>/`）：

| 文件 | 用途 |
|---|---|
| `parsed.json` | 章节 / 段落 / 字符偏移（载体无关的中间结果） |
| `analyzed.json` | 判定结果：区间、类型、证据、分数 |
| `report.txt` | 逐段对照表，核对判定时看这个 |
| `book.html` | 单文件阅读版（节选） |
| `index.html` | 分章阅读版的目录页（全书） |

build 会顺手做一次源文件体检并打一行提醒，`--skip-check` 可跳过。
交付时告诉用户：偏好不用重跑引擎，页面顶栏能实时调，翻页会把偏好带过去。

### 把书交给读者：EPUB / PDF

阅读页能调偏好，但读者往往还想把这版书搬到别的 App（Apple Books、静读天下、多看…）。
**不要用 txt**：txt 没有样式，"淡化"只能靠删段或加文字标记，等于把视觉分级降级成内容
删减。EPUB 和 PDF 都能真淡化，细节见
[references/render-spec.md](references/render-spec.md) 的「EPUB / PDF 交付规格」。

```
python scripts/run.py export <analyzed.json> --format epub          # 整本书的正路
python scripts/run.py export <analyzed.json> --format pdf --chapters-per-file 50   # 大书拆卷
```

| 载体 | 什么时候用 | 要点 |
|---|---|---|
| EPUB（默认） | 整本书，读者要导入阅读器 | 零依赖打包；每章一个 XHTML；淡化用灰色（`--lever color`）或透明度（`--lever opacity`），因为各家阅读器保留的样式不一样 |
| PDF | 节选、单卷、要打印/存档 | 走本机 Edge/Chrome 无头打印，淡化与阅读页一致；页数很大，整本必须拆（`--chapters-per-file`）或用 `--from/--to` 截一段 |

两个载体都由 `analyzed.json` 离线打包，所以拿不到浏览器里手动点过的段落；要固化某个
选择就用 `--strength` / `--keep` 明确指定。打完之后 `tests/check_pack.py` 能自检：
结构、XML、清单一致、class 与样式表一致、正文逐字保真、分层深浅单调，以及**用 poppler
量 PDF 上的墨色**，确认淡化真的落到了纸上（实测 情节 18 / 普通 47 / 注水 100）。

对面阅读器里灰色没生效时，改用 `--lever opacity` 再打一份；拿不准就先跑
`scripts/make_css_probe.py` 生成样式探针导入该阅读器，看哪些样式手段活着。

## 流程三：用户说判得不准

1. 先看证据，不要先改规则：
   ```
   python scripts/run.py sample <analyzed.json> --tier fade --n 25 --context 1
   ```
   固定种子 → 同一份结果每次抽到同一批，改规则前后能直接对比。
2. 定位到哪条判据：`report.txt` 每段都写了 `evidence`（哪条规则命中的）。
3. 改判据时守住底线：长度类阈值相对本书基线、零信息规则才允许判死、
   非情节信息一律只打标签。
4. 改完在两本以上不同风格的书上重跑同一批抽样，确认没把误报换成漏报。

## 决策点

| 决策 | 默认 | 什么时候改 |
|---|---|---|
| 单文件还是分章 | 自动：> 40 万字分章，否则单文件 | 手机上读、或用户抱怨加载慢，就提前分章 |
| 判定口径 | 数据够硬的（求票、水印、复述）判死；只相关的（标点、句长、写景）只打标签 | 只有零信息类可以判死，别把口味问题写进规则 |
| 面板数值 | 折叠成一行摘要（原文不丢，随时能展开）；设计上面板里的**异常字段**永远保护，但跨章 diff 还没接入，别承诺"伏笔已自动标出" | 系统流读者想要数值 → 换成「保留原文」 |
| 污染源 | 报给用户，不静默处理 | 用户选读干净区间 → `--limit <首个污染章-1>` |
| 章号回退 | 先跟用户确认编号口径 | 引用"第 N 章"前必须确认，否则按位置（`--from/--limit`）处理 |
| 要不要 LLM 打分 | 不接。当前是纯本地规则层，零成本、可复现 | 用户明确要求提高模糊区准确率时再说；别对外宣称已有语义打分 |
| 偏好粒度 | 按书沉淀一档，读者在页面里调 | 同书不同卷口味不同时，另存一档 |
| 交付载体 | EPUB（整本）；PDF 只给节选/单卷 | 用户要在微信读书/起点里读 → 这两个 App 不吃自定义样式，只能给 HTML；要打印 → PDF |
| 淡化杠杆（EPUB） | `color` 灰色 | 目标阅读器把灰色抹平了 → `--lever opacity`；两种都试过再决定，别猜 |

## 常踩的坑

- **别引入绝对字数阈值。** 段落中位 25 字和 35 字的两本书，同一个"短句"阈值一边误伤
  1800 多段、一边漏判。一律用 `doctor` 报出的本书基线（`book_profile` 的 p25/p50）。
- **"连续短句＝水"已被两本真书证伪**，现在只打标签不扣分，别把它读成判定。
- **作者话和系统面板必须按块判。** 逐段判只能抓到上架感言的一小部分；一块 78 段的感言
  里逐段判只能命中 9 段。
- **标点连打必须排除 `?`。** 盗版源会把 `——` / `……` 整体换成 `??`，把 `?` 算进来
  实测准确率 0%。
- **人名抽取必须过两道判据**（前置定界符比例、三字候选的前缀词频比）。只看"姓氏+词频"
  在 30 章上看不出问题，全书规模会冒出上百个假名，而假名会污染"人名首次出现"这个关键锚点。
- **全书一定分章渲染。** 369 万字单文件是 27.7 MB / 11 万 DOM 节点，Chrome 要 11 秒；
  分章后单章中位 30 KB、0.5 秒。
- **章节标题按「本书惯例 + 章号序列」两道判据认，不能只看单行长得像不像。**
  正文里整行以 `第X章` 开头的句子、盗版源在章末重贴的标题，会把一章切成碎片
  （《序列玩家》有 10 行这种）。判掉的只是"标题身份"，字一个不删。
- **别用 localStorage 存偏好。** `file://` 下各浏览器同源策略不一致，用 URL 查询串。

## 脚本

| 脚本 | 作用 |
|---|---|
| `scripts/run.py` | 唯一入口：`doctor` / `build` / `sample` 三个子命令 |
| `scripts/prescan.py` | 源文件体检 + 风格基线（doctor 第一步，也可单独跑） |
| `scripts/parse.py` | TXT → 章节 / 段落 / 字符偏移 |
| `scripts/detect_rules.py` | 规则层：零信息判定、结构与风格标签、关键锚点 |
| `scripts/tiers.py` | `kind + score` → 默认分层（引擎与渲染层共用的一份映射） |
| `scripts/report.py` | 逐段对照表 |
| `scripts/eval.py` | 按固定种子抽样审查某一层的判定 |
| `scripts/render.py` | 渲染自包含 HTML（单文件 / 分章） |
| `scripts/pack_epub.py` | 打包 EPUB（零依赖，真淡化，支持两种样式杠杆） |
| `scripts/pack_pdf.py` | 打包 PDF（本机 Edge/Chrome 无头打印） |
| `scripts/make_css_probe.py` | 生成样式探针 EPUB：实测目标阅读器保留哪些样式手段 |
| `assets/reader.html.j2` | 阅读器模板（样式、偏好控件、判定标记；`print_mode` 供 PDF 用） |
| `tests/check_pack.py` | 自检：EPUB 结构与分层样式、PDF 上的墨色深浅 |
